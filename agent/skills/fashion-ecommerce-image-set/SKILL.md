# 服装详情页

适用于同一服装商品的完整详情页、A+ 页面及页面图片组。参考服装详情页的五种视觉方向，按当前商品和用户要求选择。非服装商品、普通单张修图或几张独立商品主图不套用本流程。

## 商品与信息

- 先读取当前画布与选中节点，确认用户指定的商品、参考图、用途、数量、比例和已有内容。已知信息直接复用；只询问会实质影响交付的缺失信息。
- 商品身份保持一致：版型、结构、颜色、纹理、印花、纽扣、口袋、标识与原有文字遵循参考。不能把重新设计的款式当成同一件商品。
- 图片仅能支持实际可见的外观描述。面料成分、克重、产地、防水/防晒等性能、认证、价格、品牌历史、售后政策和尺码数值必须有用户材料依据，不根据视觉猜测，也不编造数据填满版面。
- 参考节点或资产引用不等于已经看过图片；视觉或资产工具不可用时说清限制，可根据用户文字先规划节点，不声称完成视觉核对。

## 页面规划

- 数量按用户要求；未指定时按内容选最少完整组合，通常 6–8 个模块，不固定凑数。
- 覆盖商品主视觉、核心卖点、结构细节、穿搭/使用场景及尺码/测量信息。每个模块回答不同购买问题；合并重复卖点，保留真正独立的内容。
- 尺码/测量模块与结构细节模块各自独立，不能用领口、袖口、缝线等细节替代选码信息。
- 有真实尺码数据时准确排表，逐项核对单位、行列、数值。没有数据时制作测量位置与版型参考图，不填虚构数值、S/M/L 占位表或无依据的选码结论。用户明确要求真实尺码表时集中索取数据，其余模块可先完成。
- 品牌故事、洗护、退换政策等仅在资料足够且用户需要时加入；不能把模板示例变成商品承诺。

## 视觉方向

用户指定风格优先，下列仅为可选起点：

| 方向 | 适合内容 | 视觉表达 |
| --- | --- | --- |
| 都市通勤 | 衬衫、西装、通勤裤 | 中性色、清晰网格、简洁字形、都市空间与剪裁轮廓 |
| 温柔日常 | 针织、连衣裙、家居服 | 奶油米/燕麦色、柔和自然光、舒展排版与生活场景 |
| 街头潮流 | 卫衣、工装、潮流单品 | 黑白底与少量亮色、粗字标题、动态构图、真实设计细节 |
| 户外机能 | 户外服装 | 炭黑/灰绿与功能强调色、清晰标注；技术图和数据仅据已提供事实 |
| 轻奢质感 | 精细剪裁与质感单品 | 象牙白/暖灰、克制字体、大留白、精准光线与真实肌理 |

- 同组统一商品、色彩和字体层级，按模块改变构图。交替使用主视觉、图文分栏、局部细节、测量引线及场景图，避免每张都是相同背景和大标题的海报。
- 中文请求默认中文可见文案，不添加装饰英文；原商品标识和文字保留。用户要求无字时省去新增文案。
- 卖点眉题默认纯文字，不加胶囊、徽章、底板。标题短而明确，正文只放有用信息；保证手机阅读尺寸和图文对比。

## 在 Dangoo 画布执行

1. 调用 canvas_read 获取最新节点和 revision，读取可用节点能力。先确定各模块标题、任务、参考和构图，再创建或更新本次涉及的节点，避免覆盖已有作品。
2. 为每个页面模块写完整、自洽的提示词：商品身份、参考约束、场景、光线、构图、精确可见文案、尺寸比例及禁止改动。不要使用“同上”或让后一个节点依赖聊天省略信息。
3. 通过实际支持的节点与连线组织参考、提示词和生成节点。一项独立图片结果对应一个生成节点；仅使用真实的 assetId、version 和节点 ID，不猜资源地址。
4. 生成前调用 node_quote，依照服务端费用确认流程调用 node_run。选择本 Skill 本身不构成扣费授权；不能绕过确认或直接调用外部生图服务。
5. 查询真实任务状态并将结果留在对应画布节点。生成中、失败、完成分别说明；只有实际结果存在才报告生成完成。用户只要求规划或本地 mock 时按该范围执行。

## 检查交付

检查模块分工、商品一致性、真实数据、中文文案、尺码与细节的独立性，以及当前节点和连线状态。有视觉工具与真实结果时检查错字、裁切、服装变形、重复布局；无视觉证据时明确未核验。简短说明已完成模块及仍需用户提供的数据。
